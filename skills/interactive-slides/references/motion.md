# 슬라이드 모션 패턴 카탈로그

interactive-slides 덱(1920×1080 고정 무대, `.slide.active`로 장 전환, `.step` 빌드, `Deck.demo` 훅, PDF 인쇄)에 맞춘 18개 패턴.
재현 요지는 공개 갤러리와 라이브러리 문서를 둘러보고 새로 쓴 것이며 원문 코드·프롬프트를 옮기지 않았다. 참고한 갤러리: [Jang-Go Motion Lab](https://jang-go-motion-lab.pages.dev/)(데모 코드·프롬프트의 이용 조건 표기 없음, 2026-11-19 확인 — 아이디어 참고만), Motion, GSAP, Codrops, MDN View Transitions.

## 모든 패턴에 공통인 규칙

1. **정지 상태 = 최종 상태.** 애니메이션은 `@keyframes x { from { … } }`처럼 시작 상태만 정의한다. 애니메이션이 꺼지면(PDF, 인쇄, 동작 줄이기, JS 실패) 자동으로 완성된 화면이 남는다.
2. **켜는 스위치는 하나.** `html.motion .slide.active .대상 { animation: … }`. `html.motion`은 동작 줄이기가 꺼져 있을 때만 붙인다. `.slide.active`가 다시 붙을 때마다 애니메이션이 처음부터 재생된다(뒤로 갔다 오면 다시 나옴).
3. **동작 줄이기.** 템플릿의 `@media (prefers-reduced-motion: reduce)` 규칙은 유지. JS 모션(카운트업, 모핑)은 `Deck.reducedMotion`이면 최종값을 바로 그린다. 리허설 PC가 OS 설정 때문에 reduce를 보고하면 `?motion`으로 강제 켜기(샘플 덱 방식: 강제 시 `animation` 단축 속성에 `!important`).
4. **한 장에 한 패턴, 1초 안팎.** 등장 전체가 1.2초를 넘으면 발표자가 기다려야 한다. 흐름 드로잉처럼 순서가 정보인 경우만 3초까지.
5. **장식 금지.** 움직임이 순서·변화·대응·강조 중 하나를 전달하지 않으면 뺀다.
6. **색·이징은 토큰에서.** `--accent`, `--ease`(템플릿: `cubic-bezier(0.16, 1, 0.3, 1)`).

표기: 저사양 = 내장 GPU 노트북에서 문제가 생길 가능성이 낮음(내 판단). ⚠ 프로젝터 = 발표용 노트북·프로젝터에서 위험.

## 섹션 전환

### S1 원형 클립 확장
- **모습**: 화면 한 귀퉁이 점에서 원이 커지며 섹션 슬라이드(강조색 배경)가 열린다.
- **출처**: MDN View Transitions 예제(CC0).
- **기술·저사양**: `clip-path: circle()` 키프레임. 저사양 예.
- **PDF/정지**: 섹션 슬라이드 전체.
- **동작 줄이기**: 즉시 표시.
- **재현 프롬프트 요약**: "statement 슬라이드에 클래스 하나를 주고, 활성 시 circle(0% at 8% 92%) → circle(150% at 8% 92%) 0.9초, ease-in-out."
- **주의**: 섹션 경계에만(덱 전체 2–4회). 장 크로스페이드(0.35초)와 겹쳐 보인다. 템플릿은 `?motion`일 때 OS의 동작 줄이기 설정을 무시하므로 리허설에서도 같은 모습이 나온다.

### S2 공유 요소 확대
- **모습**: 목차 카드 하나가 제자리에서 커져 다음 장의 제목 띠가 된다.
- **출처**: View Transitions API(MDN·Chrome 문서), GSAP Flip, Motion layout 애니메이션.
- **기술·저사양**: `document.startViewTransition()` + `view-transition-name`. Baseline 2025라 구형 브라우저는 그냥 컷. 저사양 예.
- **PDF/정지**: 두 장이 각각 완성 상태.
- **동작 줄이기**: 전환 생략(컷).
- **재현 프롬프트 요약**: "목차 카드와 다음 장 제목 띠에 같은 view-transition-name을 주고, 장 전환을 startViewTransition으로 감싼다. 미지원 시 기존 show() 그대로."
- **주의**: 템플릿 런타임 `show()`는 수정하지 않는 것이 스킬 규칙. 런타임을 건드리지 않으려면 FLIP(위치 측정 후 transform)으로 데모 쪽에서 구현. 발표자 보기(iframe)에서는 전환이 두 번 보일 수 있음(미검증).

### S3 글자 창 전환
- **모습**: 큰 단어(예: 섹션 번호)의 글자 모양 안으로 다음 장이 비쳐 보이다가 화면 전체가 된다.
- **출처**: .
- **기술·저사양**: SVG `<clipPath>`에 `<text>`, scale 애니메이션. 저사양 예.
- **PDF/정지**: 다음 장 완성 상태.
- **동작 줄이기**: 컷.
- **재현 프롬프트 요약**: "섹션 숫자 한 글자를 clipPath로 쓰고 다음 장 배경을 그 안에 그린 뒤 1.0초 동안 scale 1→40으로 키워 화면을 덮는다."
- **주의**: 한글 글자 획이 얇은 서체는 창이 좁다. 굵은 숫자 하나가 안전. 연구 발표에서는 기조 강연·강의 정도에만.

## 숫자·그래프 등장

### D1 카운트업 숫자
- **모습**: 핵심 수치가 0에서 실제 값까지 1초 안에 올라간다.
- **출처**: GSAP·anime.js 데모의 흔한 패턴. 라이브러리 불필요.
- **기술·저사양**: `Deck.demo`의 `enter`에서 0으로 놓고 `api.raf`로 easeOutCubic 보간. 저사양 예.
- **PDF/정지**: **마크업에 최종 값을 써 둔다**(JS가 실행 안 돼도 맞는 숫자).
- **동작 줄이기**: `enter`에서 아무것도 안 함.
- **재현 프롬프트 요약**: "`.count[data-to][data-dec]` 요소들을 enter에서 0으로, 1.1초 동안 easeOutCubic으로 data-to까지, toFixed(data-dec). leave에서 최종값으로 복원."
- **주의**: 소수 자릿수를 처음부터 고정(자릿수 변화로 폭이 흔들림). 신뢰구간·p값처럼 "크기"가 의미 없는 숫자엔 쓰지 않는다. 카드 2–3개까지.

### D2 0에서 자라는 막대
- **모습**: 막대가 기준선(0)에서 오른쪽으로 차례로 자라고, 값 라벨이 뒤따라 나타난다.
- **출처**: .
- **기술·저사양**: SVG rect에 `transform-box: fill-box; transform-origin: left` + scaleX. 저사양 예.
- **PDF/정지**: 완성 차트.
- **동작 줄이기**: 즉시 완성.
- **재현 프롬프트 요약**: "viz가 그린 rect에 순서 인덱스를 붙이고, 활성 시 scaleX(0)에서 0.8초, 막대 간 0.11초 지연. 값 텍스트는 막대가 끝날 즈음 페이드."
- **주의**: 막대는 반드시 0에서 시작(스킬 규칙과 동일). 축을 자른 차트에 성장 모션을 붙이면 차이를 과장한다. 강조 막대 하나만 강조색.

### D3 선 그래프 드로잉
- **모습**: 학습 곡선·용량-반응 곡선이 왼쪽에서 오른쪽으로 그려지고, 끝점 라벨이 마지막에 나온다.
- **출처**: GSAP DrawSVG(무료), CSS `pathLength="1"` + stroke-dashoffset.
- **기술·저사양**: SVG. 저사양 예.
- **PDF/정지**: 완성 곡선.
- **동작 줄이기**: 즉시 완성.
- **재현 프롬프트 요약**: "lines 차트의 polyline에 pathLength=1, dasharray 1, 활성 시 dashoffset 1→0을 1.2초 linear. 기준 곡선은 정지, 비교 곡선만 그린다."
- **주의**: 시간축이 있는 데이터에만. 점(circle)은 선이 지나갈 때 같이 나와야 어색하지 않다.

## 구조·흐름 설명

### F1 경로 드로잉 + 노드 순차 점등
- **모습**: 파이프라인 상자가 하나씩 나타나고 사이 화살표가 그려진다. 되돌아가는 화살표는 맨 마지막.
- **출처**: GSAP DrawSVG 데모, Motion 예제의 path drawing.
- **기술·저사양**: 인라인 SVG + CSS. 저사양 예.
- **PDF/정지**: 완성 도식.
- **동작 줄이기**: 즉시 완성.
- **재현 프롬프트 요약**: "노드 g와 edge path에 같은 순서 인덱스를 주고, 노드는 0.42초 간격 pop, 엣지는 해당 노드 직후 dashoffset 드로잉. 피드백 엣지는 다른 색으로 모든 것이 끝난 뒤 0.8초."
- **주의**: 화살촉(marker)은 dash가 적용되지 않아 선보다 먼저 보인다. 화살촉이 필요하면 선이 끝난 뒤 따로 페이드. 노드 8개 넘으면 단계별 공개(R1)로 나눈다.

### F2 모핑
- **모습**: 같은 네 상자가 "기술 분류 도식"에서 "컨셉 수 막대 차트"로 형태를 바꾼다. 버튼으로 왕복.
- **출처**: GSAP MorphSVG(무료, 경로 모핑이 필요할 때).
- **기술·저사양**: 사각형이면 x/y/w/h 보간만으로 충분(라이브러리 불필요). 임의 경로는 점 개수를 맞춰야 함. 저사양 예.
- **PDF/정지**: 결론 쪽 상태(차트)를 기본값으로.
- **동작 줄이기**: 결론 상태만, 버튼은 즉시 전환.
- **재현 프롬프트 요약**: "두 상태의 사각형 배열 A, B를 정의하고 p∈[0,1]을 easeInOutCubic으로 보간해 rect·라벨 좌표를 갱신. enter 시 A에서 0.6초 대기 후 1.2초에 B로."
- **주의**: "같은 대상이 다른 관점으로 보인다"는 뜻이 있을 때만. 서로 다른 것을 모핑하면 대응 관계를 잘못 암시한다.

### F3 경로 위를 지나는 데이터 점
- **모습**: 작은 점이 파이프라인 경로를 따라 흘러 데이터 흐름 방향을 보여 준다.
- **출처**: CSS `offset-path`(브라우저 내장).
- **기술·저사양**: CSS offset-path + offset-distance 반복 애니메이션. 저사양 예(점 몇 개).
- **PDF/정지**: 점을 빼고 화살표만 남는 것이 자연스럽다(점은 `@media print { display:none }`).
- **동작 줄이기**: 점 숨김.
- **재현 프롬프트 요약**: "edge와 같은 path 문자열을 offset-path로 쓰는 원 3개를 1/3 주기씩 어긋나게 2.4초 무한 반복."
- **주의**: 무한 반복은 이 패턴만 허용, 그래도 한 장에 한 경로. 말하는 동안 계속 움직여 시선을 빼앗으므로 설명이 끝나면 다음 장으로.

## 단계별 공개

### R1 공개 + 이전 단계 흐리게
- **모습**: → 키마다 카드가 하나씩 나오고, 이미 나온 카드는 40% 불투명도로 물러난다.
- **출처**: 템플릿 `.step` 빌드 + CSS `:has()`. 발표 도구의 "dim previous" 관행.
- **기술·저사양**: CSS. 저사양 예.
- **PDF/정지**: 템플릿 print 규칙이 모든 step을 불투명도 1로 강제 → 전부 진하게. 흐리게 규칙은 `@media screen` 안에 둔다.
- **동작 줄이기**: 전환 시간만 0, 흐리게는 유지(정보이므로).
- **재현 프롬프트 요약**: "`.step.shown:has(~ .step.shown)`에 opacity .4와 scale(.97)을 화면 전용으로."
- **주의**: 셋에서 다섯 단계까지. 흐린 단계도 읽을 수 있어야 한다(프로젝터 대비가 낮으면 .4가 거의 안 보임 → .5).

### R2 큰 그림 안에서 줌·이동
- **모습**: 전체 아키텍처 그림을 먼저 보여 주고, 단계마다 해당 블록으로 확대·이동한다.
- **출처**: Prezi식 줌의 단순형.
- **기술·저사양**: 그림 컨테이너에 `transform: translate() scale()` 전환, step마다 값 변경. 저사양 예(단, 큰 비트맵 확대는 흐려짐).
- **PDF/정지**: 전체 그림(줌 아웃 상태).
- **동작 줄이기**: 이동 없이 해당 블록 테두리 강조로 대체.
- **재현 프롬프트 요약**: "SVG 그림 하나에 영역 좌표 배열을 두고, 단계 i에서 컨테이너를 그 영역이 무대에 꽉 차도록 0.8초 변환."
- **주의**: 래스터 그림은 원본 해상도가 확대 배율만큼 높아야 한다. 확대 후 글자가 22px 미만이면 의미 없음. 멀미 유발 가능 → 줌은 한 덱 한 번.

## 강조 하나

### E1 스포트라이트
- **모습**: 차트 막대가 모두 같은 진하기로 나온 뒤, 1초쯤 지나 핵심 막대만 남기고 나머지가 회색으로 물러난다.
- **출처**: 데이터 시각화 강조 관행, 템플릿 hbars의 `fade` 속성.
- **기술·저사양**: CSS (`from { opacity: 1 }`만 정의, 최종 불투명도는 SVG 속성). 저사양 예.
- **PDF/정지**: 이미 흐려진 최종 상태(강조가 남는다).
- **동작 줄이기**: 최종 상태.
- **재현 프롬프트 요약**: "fade 행을 opacity .4로 그려 두고, 활성 시 1.1초 지연 후 0.6초 동안 1에서 .4로 내려오는 애니메이션만 건다."
- **주의**: 한 장에 강조 하나(사용자 규칙). 프로젝터에서 회색과 흰 배경 대비가 사라질 수 있으니 회색 막대에 값 라벨 유지.

### E2 형광펜 스윕
- **모습**: 마무리 문장의 핵심 구절 아래로 반투명 띠가 왼쪽에서 오른쪽으로 칠해진다.
- **출처**: 템플릿 `.hl` 스타일을 움직이게 한 것.
- **기술·저사양**: `background-size: 0% 100%` → 100%. 저사양 예.
- **PDF/정지**: 칠해진 띠.
- **동작 줄이기**: 칠해진 띠.
- **재현 프롬프트 요약**: "구절 span에 아래 40% 높이 그라데이션 배경을 깔고, 활성 시 0.5초 지연 후 0.9초 동안 background-size 가로를 0에서 100%로."
- **주의**: 구절이 줄바꿈되면 띠가 줄마다 따로 칠해지지 않고 한 덩어리로 움직인다(`box-decoration-break: clone` 고려). 문장당 한 곳.

### E3 렌즈·와이프 비교
- **모습**: 원본 영상 위로 원형 렌즈(또는 세로 경계선)가 지나가며 안쪽에 분할 결과·열지도가 보인다.
- **출처**: 스킬 demos.md 패턴 5(before/after wipe).
- **기술·저사양**: 두 이미지를 겹치고 위 이미지에 `clip-path: circle(r at x y)` 또는 inset. WebGL 굴절 없이 충분. 저사양 예.
- **PDF/정지**: 경계 50% 위치(양쪽이 다 보이게).
- **동작 줄이기**: 자동 이동 없이 슬라이더 조작만.
- **재현 프롬프트 요약**: "같은 크기 이미지 두 장을 겹치고, 슬라이더 또는 정해진 세 지점 경로로 원형 clip-path 중심을 이동. 렌즈 테두리 2px 강조색."
- **주의**: 공개 가능한 자료만 쓴다(내부 데이터·개인정보 금지). 두 이미지 정합이 1px만 어긋나도 "결과가 움직인다"로 오해된다.

## 프로젝터 노트북 점검 목록

1. 발표 노트북에서 `matchMedia('(prefers-reduced-motion: reduce)').matches` 확인. true면 `?motion` 주소로 리허설·발표하거나 OS 애니메이션 설정을 켠다.
2. 외부 화면 미러링 상태에서 Canvas/WebGL 장을 30초 돌려 끊김 확인(⚠ 표시 패턴).
3. 와이파이를 끄고 덱을 열어 CDN 의존 장의 폴백 확인.
4. PDF를 인쇄해 모든 장이 최종 상태로 나오는지 확인(스킬의 `render_slides.py --mode pdf`).
